## Authentication errors

FangDash signs you in with Twitch through Better Auth. Twitch is the only social provider, so most auth issues trace back to the OAuth redirect or missing API secrets.

### OAuth redirects to a blank page or error

**Cause:** The Twitch OAuth redirect URL doesn't match the configured callback.

**Fix:** In the [Twitch Developer Console](https://dev.twitch.tv/console), make sure the redirect URL is one of:

- Local: `http://localhost:8787/api/auth/callback/twitch`
- Production: `https://your-api-domain.workers.dev/api/auth/callback/twitch`

The URL must match **exactly**, including protocol and path.

### "Auth not configured" (503)

**Cause:** One or more required auth environment variables are missing on the API.

**Fix:** Set all required secrets:

```bash
bunx wrangler secret put BETTER_AUTH_SECRET --env production
bunx wrangler secret put TWITCH_CLIENT_ID --env production
bunx wrangler secret put TWITCH_CLIENT_SECRET --env production
```

### Token expired / session invalid

**Cause:** Your session cookie is stale. Better Auth uses a short cookie cache (5 minutes), so a fresh session state is re-fetched shortly after it goes out of date.

**Fix:** Sign out and back in. The browser usually recovers on its own — if it doesn't, clear cookies for the site and sign in again.

## API errors

The API is a Hono app on Cloudflare Workers exposing tRPC v11 endpoints. Errors come back as standard HTTP status codes.

### 401 Unauthorized

**Cause:** No valid session. The request requires you to be signed in.

**Fix:** Sign in first. If you're already signed in, your session may have lapsed — refresh the page.

### 403 Forbidden

**Cause:** One of:

- Your account is **banned**
- You're hitting an admin-only endpoint without the right role
- Your ban hasn't expired yet

**Fix:**

- If banned: contact the server admin, or wait for the ban to expire (bans can be permanent or time-limited)
- If accessing the admin panel: make sure your user has the `admin` role (see the [Admin docs](/docs/getting-started/admin))

### 429 Too Many Requests

**Cause:** You've exceeded the rate limit — **10 mutations/min** or **60 queries/min** per user.

**Fix:** Wait for the duration in the `Retry-After` response header (usually under a minute), then retry.

### 500 Internal Server Error

**Cause:** An unexpected server error, usually a database problem or an unhandled exception.

**Fix:**

- Tail the Cloudflare Workers logs in real time with `bunx wrangler tail`, or read them in the Cloudflare dashboard
- Common culprits: a missing D1 binding, an unmigrated database, or a transient network issue

## Database errors

FangDash stores everything in Cloudflare D1 (SQLite) via Drizzle ORM and migrations.

### "table not found"

**Cause:** Migrations haven't been applied to the database.

**Fix:**

```bash
bunx wrangler d1 migrations apply fangdash-db --remote
```

### UNIQUE constraint violation

**Cause:** An attempt to insert a duplicate row — for example, unlocking the same achievement twice, or replaying a run with the same `(player, seed)` pair (replay protection is enforced on scores).

**Fix:** This is normally handled gracefully by the app. If it persists, inspect the affected table for duplicate entries.

### "database is locked"

**Cause:** Too many concurrent writes to D1.

**Fix:** This is transient — retry the operation. If it happens often, look for expensive queries or missing indexes.

## WebSocket / multiplayer errors

Real-time races run on a PartyKit WebSocket server. Rooms hold up to 4 players and are authenticated with a short-lived token minted by the API.

### Connection refused to PartyKit

**Cause:** The PartyKit server isn't running, or the host URL is wrong.

**Fix:**

- Verify PartyKit is deployed: `bun run ship:party`
- Check that `NEXT_PUBLIC_PARTYKIT_HOST` matches your deployment URL
- The host should look like `fangdash.your-username.partykit.dev` (no `https://` prefix)

### Race token rejected / connection closed on join

**Cause:** The connection token is missing, expired, or signed with a different secret. The web client fetches a token from `race.getConnectionToken` (an HMAC-SHA256 token with a 120-second TTL) and passes it to PartyKit as `?token=`.

**Fix:** Make sure `RACE_TOKEN_SECRET` is set to the **same value** on both `apps/api` and `apps/party`. If the token simply timed out, rejoin the race so the client mints a fresh one.

### "Room not found" or empty room state

**Cause:** The race room doesn't exist on the PartyKit server, or the server was restarted.

**Fix:** PartyKit rooms are ephemeral — if the server restarts, active rooms are lost. Create a new room from the lobby.

### Players disconnecting during a race

**Cause:** Network instability or a PartyKit connection timeout.

**Fix:**

- The game handles drops gracefully — disconnected players are removed, and the host migrates if the host leaves
- If everyone disconnects, the race ends automatically
- Check the browser console for WebSocket error messages

### Malformed messages rejected

**Cause:** The client sent a WebSocket message that doesn't match the expected schema.

**Fix:** This is a client-side bug. Every message is validated against a Zod schema before processing. Check the browser console for details. If you're building a custom client, match the message shapes exported from `@fangdash/shared` (`ws-schemas.ts`).

## Build & deploy errors

### Type errors after pulling changes

**Fix:** Reinstall dependencies and re-run the type checker:

```bash
bun install
bun run typecheck
```

### Deploy fails with "not found" errors

**Cause:** Build artifacts are stale.

**Fix:**

```bash
bun run clean
bun run build
bun run ship
```

### PartyKit deploy fails with an auth error

**Cause:** A missing or expired `PARTYKIT_TOKEN`.

**Fix:**

```bash
export PARTYKIT_TOKEN=your-token-here
bun run ship:party
```

<Callout type="info">
	Still stuck? Double-check your environment variables against the setup guide, then confirm every
	app is on Node.js 20 or newer and running the same `RACE_TOKEN_SECRET` across the API and party
	server.
</Callout>
